# Verify downloads before finalization

a365dt downloads into a resumable `.part` file, accepts completion only when range responses and the final byte count agree with the server, flushes the file, and atomically renames it. A partial file keeps the server's HTTP validator so retries only append bytes from the same media asset; otherwise the transfer restarts safely. Transient failures get three retries with a freshly resolved media URL; an exhausted transfer keeps its `.part` for the next run while unrelated Episodes continue. An existing final file with the expected byte length is trusted and skipped; a length mismatch is kept with a `.corrupt` suffix until a verified replacement succeeds, then removed. This prevents interrupted transfers from appearing complete while leaving only the requested media after success; it deliberately does not attempt to detect corruption that occurs later without changing file size.
