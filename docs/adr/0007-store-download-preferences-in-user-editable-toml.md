# Store download preferences in user-editable TOML

a365dt stores only the output directory, concurrent download count, and whether to mux without confirmation as optional keys in the Application home's flat, unversioned `config.toml`; omitted keys use built-in defaults, unknown or invalid values fail downloads and appear as an error in `doctor`, and unrelated maintenance commands remain available. Explicit CLI values take precedence, configured output paths must be absolute or `~/`-prefixed and outside the Application home, muxing disabled in the file preserves the existing prompt, and job counts above 10 remain valid but warn once per Download Invocation.

`a365dt config` edits all effective values interactively and replaces readable but invalid content only after confirmation; unreadable files remain untouched. `config show` displays resolved values with their sources, `config reset` removes only this file after confirmation, writes are atomic, and configuration commands are not recorded as telemetry. TOML is preferred over the already available JSON support because the file is user-edited, while environment-variable preferences, profiles, an initial schema identifier, comment-preserving rewrites, and configuration locking are deferred until demonstrated need; an Application-home migration preserves a pre-existing `config.toml` verbatim before normal validation.
